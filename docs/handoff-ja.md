現在の画面は四つです。

1. **ひと続きで見る**：既定画面。左から右へ流れる情報が思考の引力で曲がって集まる様子、共有、成長と、同じ受信区間の二つの時計を一つの図で表示する。薄い輪は、思考がなければ通っていた位置。
2. **情報が集まり、集める力も育つ**：同じ流れで、隣の収集者、共有、蓄積による成長の有無を比較する。
3. **重力と時間の尺度**：静的な質量条件を変え、無限遠の時計と近くで静止した時計を比較する。
4. **作用反作用**：等大・逆向きの力と、質量比による動きの違いを表示する。

既定画面は固定条件です。詳細画面で保持している設定を混ぜません。自動再生や無限ループはなく、ボタンで開始・一時停止・再開・繰り返しを操作します。動きを減らす設定では終了状態を表示します。

## 起動と編集

リポジトリ内の `simulator/index.html` をブラウザーで開けば動きます。HTTP経由で確認する場合は、チェックアウトのルートで次を実行できます。

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory simulator
```

ブラウザーで `http://127.0.0.1:8000/` を開きます。ポートが使用中なら番号を変えてください。配信を終えるときは `Ctrl+C` で停止します。

以前案内した `http://127.0.0.1:36989/?view=receiver-time` は一時プレビュー用です。確認時点ではサーバーが停止しており、恒久的な参照先には使えません。開いているタブには古い画面が残ることがあるため、ファイル更新後は再読み込みしてください。ブラウザーや実行環境が `file:` URLを扱えない場合は、HTTPで確認してください。

編集するときは `source.html` を修正し、**`index.html` とインライン表示用コピーにも反映**してください。`source.html` を単純に `index.html` へコピーすると、表示用のスタイルや保存機能の枠組みが失われます。

元の開発環境では、Git管理外の `work/export_simulator.py` が表示ホストのrendererを使って書き出し、不要な外部スクリプト読み込みを除去しています。この書き出しツールはcloneだけでは揃いません。別のAIがこのツールを使えない場合は、`source.html` の修正ファイルまたは差分を返し、元の開発環境で単独HTMLと会話内表示を同期できます。単独HTMLの生成を検証していない場合は、その旨を明記してください。

## 数値モデルと確認結果

詳しい仮定は [model-notes-ja.md](model-notes-ja.md) を参照してください。変更後の確認に使える主な値は次のとおりです。

| 項目 | 現在の設定・期待結果 |
| --- | --- |
| 情報粒子 | 画面内72個＋上流65個＝137個、固定シード38123、計算領域400×240。左から右へ流速60（±10%） |
| 共有 | 一方向のコピー。収集者の元情報は残り、取得済みIDは重複して数えない |
| 成長 | `1 + 1.8 × min(K / 48, 1)`、上限2.8倍 |
| 既定画面の終了時 | 直接取得29＋共有51＝異なる情報80点 |
| 単独で成長なし | 21点 |
| 単独で成長あり | 25点 |
| 隣あり・成長あり・共有なし | 21点。隣の引力だけで自分の取得が増えるとは限らない |
| 既定画面の再生 | 約6.5秒。表示上は外の時計の10秒へ換算 |
| 既定画面の手元の時計 | `u = 0.6`、外10秒に対し約6.324555320秒 |
| 時計の詳細画面 | `u = 0 / 0.6 / 0.8` で、局所経過時間は `10 / 約6.324555 / 約4.472136秒` |
| 作用反作用 | 質量が2倍の物体の変位は、同じ条件の質量1の物体の半分 |

時計は、球対称・非回転・無電荷の重力源の外で静止した時計と無限遠を比較するモデルです。進行比は `√(1 − u)`、`u = 2GM / (rc²)` です。粒子の引き寄せ・捕捉・共有と時計は独立した計算で、成長する引力と時空の連成計算ではありません。情報のコピーは理解・学習の成立を保証しません。

### 保存処理で修正した実行エラー

`window.openai.setWidgetState` の戻り値に直接 `.catch()` を呼ぶと、値を返さない保存APIでは、再生終了や場面変更の直後に `Cannot read properties of undefined (reading 'catch')` が発生します。単独HTML側の保存APIはPromiseを返すため、単独版の検証だけでは見落としていました。

現在は `Promise.resolve(window.openai.setWidgetState(...)).catch(...)` とし、値を返さない場合とPromiseを返す場合の両方に対応しています。[OpenAI公式ドキュメント](https://developers.openai.com/plugins/build/chatgpt-ui#keep-temporary-ui-state-in-the-ui)も参照できます。

値を返さない・成功したPromise・拒否されたPromise・APIなしの条件と、実際のアニメーション終了・場面切り替えを模擬インライン環境で検証済みです。一方、実アプリで表示された一般メッセージ `Inline visualization failed while running` の元の例外は取得できていません。修正後の実際のCodex内インライン表示での完走・解消確認も、この検証記録には含まれていません。この修正を、あらゆる同名エラーの原因確定と読み替えないでください。再発した場合は、初期表示直後か、再生終了・場面変更後かを分けて調べてください。

## 共同開発を始めるとき

開発元を正本とし、公開用コピーは共有先として扱います。公開用コピーへの変更は開発元に自動では戻りません。変更を受け取ったら、開発元でレビュー・検証して作業ブランチへ反映し、必要に応じて公開用コピーを更新してください。

1. この文書、README、モデル説明を読み、実装があるブランチを確認する。
2. 公開ソースを取得する。取得機能がない場合はZIPまたはファイル添付を使う。書き込みを担当する場合のみ、その環境のGitHub認証と権限を確認する。
3. 既存チェックアウトを使う場合は `git status` と履歴を確認し、他者の未コミット変更やリモートの新しい変更を上書きしない。
4. 現在の表示を起動し、ユーザーから担当する変更内容を受け取る。この文書自体を、新しい機能追加の依頼とは扱わない。
5. ソース・単独HTML・必要なインラインコピーを同期し、変更に見合う検証と説明文の更新を行う。
6. 書き込み接続がある場合は、英語のConventional Commitsで変更をまとめ、作業ブランチ・PRで共有する。接続がない場合は修正ファイルまたは差分を返し、反映担当へ渡す。`main` / `master` へ直接pushしない。

適用されている開発方針には、原因を隠さず修正すること、振る舞いを確認すること、依存を必要以上に増やさないこと、秘密情報をソースへ書かないこと、変更と文書を揃えることがあります。現時点でライセンスは指定していません。

別のAIへ依頼するときは、[Claudeなど別のAIへ渡す手順](claude-start-ja.md)の依頼文を使えます。公開ブランチのURL、またはZIPとこの文書を渡してください。
